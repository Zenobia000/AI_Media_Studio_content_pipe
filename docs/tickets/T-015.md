# T-015｜Skill 框架：SKILL.md 格式、RESOLVER、工具介面契約

| 負責人 | Sprint | 估點（人天） | 類型 | Epic |
|---|---|---|---|---|
| 周長曉 | S1 | 2 | feature | [E01-core](E01-core.md) |

**前置票**：[T-002](T-002.md)

**實作需求**：`AGT-FR-001`、`AGT-FR-002`、`AGT-FR-003`、`IF-019`、`IF-020`、`NFR-009`

## 背景

2026-10-24 由「LLM adapter」改為本票（ADR-09）：工具不再呼叫 LLM，判斷與寫作交給 agent 依 skill 執行。這張票定下所有人寫 skill 和工具的共同格式，是 S2 所有 skill 的前置。

## 要做的事

- [ ] IF-019：SKILL.md front-matter 的 JSON Schema 與範本 `skills/_template/SKILL.md`
- [ ] `skills/_conventions/`：輸出格式、關卡（哪些工具要人確認）、失敗時的處理方式
- [ ] `skills/RESOLVER.md` 第一版：口語需求 → skill 對照
- [ ] 工作區 `CLAUDE.md` 範本（≤ 200 行），給 T-008 的 init 使用
- [ ] IF-020：工具輸出 envelope 的 helper（`ok`、`data`、`error_code`、`message`、`next`）與結束碼
- [ ] `newsroom tools --json` 與 `tools --check-skills`

## 交付物

- `schemas/skill.schema.json`、`schemas/tool-output.schema.json`
- `skills/_template/`、`skills/_conventions/`、`skills/RESOLVER.md`
- `src/newsroom/toolkit.py`（envelope helper）、工具 `tools`

## 驗收標準

1. Given 一份缺少 `tools` 欄位的 SKILL.md，When `tools --check-skills`，Then 指出檔案與欄位
2. Given 用 helper 寫的 EchoStep 工具，When 給錯參數，Then 輸出合法的 IF-020 JSON 且結束碼為 2
3. Given `tools --json`，When agent 讀取，Then 每個工具都有名稱、參數與一句說明

## 測試方式

pytest（schema 與 envelope 契約測試）；在 fixture 工作區開 Claude Code 確認看得到範本 skill。

## 不在這張票的範圍

各環節的 skill 內容（由各模組擁有者寫）；eval 工具（T-110）；headless 執行（T-048）。
