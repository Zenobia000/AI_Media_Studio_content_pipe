## 背景

三個人第一天就要有同一個 repo 結構、同一套測試與檢查，否則之後的合併會一直衝突。

## 要做的事

- [ ] 建立 poetry 專案與 `src/newsroom/` 目錄結構（依架構文件 §4.1）
- [ ] Typer CLI 入口 `newsroom --version`
- [ ] pytest、ruff、mypy 設定
- [ ] GitHub Actions：lint、型別檢查、測試（不連網）
- [ ] README：WSL 建置步驟（pyenv＋poetry）
- [ ] 建立 `skills/` 目錄與 `skills/RESOLVER.md` 空殼（內容由 T-015 定義）
- [ ] 開發用 `CLAUDE.md`：指向架構文件、SRS 與 skill 規則

## 交付物

- `pyproject.toml`、`src/newsroom/cli.py`
- `.github/workflows/ci.yml`
- README 建置章節

## 驗收標準

1. Given 乾淨的 WSL，When 依 README 執行建置與 `newsroom --version`，Then 印出版本號
2. Given 一個 PR，When CI 執行，Then lint、型別檢查、測試都會跑而且不需要網路
3. Given 有人提交型別錯誤的程式，When CI 執行，Then CI 失敗並指出位置

## 測試方式

CI 本身就是測試；另外在乾淨的 WSL 照 README 建置一次。
