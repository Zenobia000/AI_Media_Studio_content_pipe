# T-009｜執行紀錄 ledger：run_id、Job、指紋、鎖

| 負責人 | Sprint | 估點（人天） | 類型 | Epic |

**前置票**：[T-007](T-007.md)

**實作需求**：`CORE-FR-010`、`CORE-FR-011`、`AGT-FR-004`、`IF-014`、`IF-015`、`NFR-003`

## 背景

原本的 Job 協調器不再決定流程順序（ADR-09），只負責讓每次工具呼叫都可追溯、冪等、不撞車。agent 會重試、會亂序呼叫，這一層要讓它們都安全。

## 要做的事

- [ ] 定義 `Step` Protocol 與 `StepResult`（IF-015），作為每個工具的內部實作
- [ ] Job 建立、狀態轉換、結果記錄；Job 帶 `run_id`（從環境變數 `NEWSROOM_RUN_ID` 讀）
- [ ] `agent_runs` 資料表與 run 的建立、結束、花費寫入
- [ ] 指紋：相同指紋而且已成功時不重跑
- [ ] 鎖：SQLite locks 表＋PID＋心跳；失效可接手
- [ ] 提供一個 `EchoStep` 範例工具與測試，讓其他人照著寫

## 交付物

- `ledger/step.py`、`jobs.py`、`locks.py`、`runs.py`
- `docs/how-to-write-a-tool.md`

## 驗收標準

1. Given 同一個 Step 與相同輸入，When 連續執行兩次，Then `run` 只被呼叫一次
2. Given 兩個程序同時執行同一目標，When 第二個取鎖，Then 得到 E_LOCKED
3. Given 持有鎖的程序被 kill，When 下一次執行，Then 可以取得鎖
4. Given 設定了 `NEWSROOM_RUN_ID` 的三次工具呼叫，When 查詢該 run，Then 依時間列出三個 Job

## 測試方式

pytest，含多程序並行測試。

## 不在這張票的範圍
