| 負責人 | Sprint | 估點（人天） | 類型 | Epic |

| 楊舒媁 | S2 | 1 | feature | [E01-core](E01-core.md) |

**前置票**：[T-009](T-009.md)、[T-019](T-019.md)

**實作需求**：`CORE-FR-015`、`NFR-010`、`US-003`

## 背景

人每天看進度的地方。

## 要做的事

- [ ] 彙整 Content 與 Job，排序：blocked → failed → running → done
- [ ] 每一項附下一步建議（skill 或工具）
- [ ] `--run <run_id>`：列出那次 agent 執行的工具呼叫、結果與花費
- [ ] 更新 topic.md、content.md 的狀態受管區塊
- [ ] `skills/recover/SKILL.md`：讀 status，決定重跑哪一步或請人處理

## 交付物

- 工具 `status`、`skills/recover/`

## 驗收標準

1. Given 一個缺錄音（blocked）與一個 API 錯誤（failed），When status，Then 兩者都附正確的下一步建議
2. Given topic.md 有人寫的內容，When status 更新摘要，Then 只有受管區塊改變
3. Given 使用者問「剛剛為什麼失敗」，When agent 用 recover skill，Then 回答引用 status 的錯誤碼並提出重跑方式

## 測試方式

pytest＋CliRunner。
