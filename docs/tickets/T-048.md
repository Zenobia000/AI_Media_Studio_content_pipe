# T-048｜排程器：收集排程與 headless skill 執行（newsroom run）

| 負責人 | Sprint | 估點（人天） | 類型 | Epic |
|---|---|---|---|---|
| 楊舒媁 | S3 | 3 | feature | [E10-ops](E10-ops.md) |

**前置票**：[T-009](T-009.md)

**實作需求**：`OPS-FR-001`、`AGT-FR-006`、`US-090`

## 背景

inbox 每天自動更新、早報與週報自動產生的前提。不需判斷的工作直接執行工具，需要判斷的用 `claude -p` 跑 skill（ADR-09）。

## 要做的事

- [ ] `newsroom scheduler install|uninstall|status`（systemd timer；fallback cron）
- [ ] 收集排程（預設 15 分鐘），直接執行 `collect` 工具；前一輪未結束時跳過（靠鎖）
- [ ] 工具 `run <skill>`：包裝 `claude -p`，設定最大回合數、花費上限、逾時；設定 `NEWSROOM_HEADLESS` 與 `NEWSROOM_RUN_ID`
- [ ] 讀取 `claude -p` 的 JSON 輸出，花費寫入 agent_runs 與 spend；失敗或逾時通知
- [ ] 排程設定支援「工具」與「skill」兩種工作

## 交付物

- `ops/scheduler.py`、`ops/headless.py`、工具 `scheduler`、`run`

## 驗收標準

1. Given 安裝排程後重開 WSL，When 等 15 分鐘，Then 日誌有一筆收集紀錄
2. Given 一個會無限重試的假 skill，When `run`，Then 達到最大回合數後停止，agent_runs 記錄 max_turns 並通知
3. Given headless 執行中 agent 呼叫 approve，When 工具檢查，Then 被拒絕（AGT-FR-005）

## 測試方式

pytest（以假的 `claude` 執行檔模擬輸出）；WSL 實機安裝一次。

## 不在這張票的範圍

早報、週報 skill 的內容（T-080、T-051）。
