# T-110｜Skill eval 工具（newsroom eval）

| 負責人 | Sprint | 估點（人天） | 類型 | Epic |
|---|---|---|---|---|
| 周長曉 | S1 | 1 | feature | [E01-core](E01-core.md) |

**前置票**：[T-015](T-015.md)、[T-003](T-003.md)

**實作需求**：`AGT-FR-007`

## 背景

skill 的結果每次可能不同（ADR-09 的代價），所以每個 skill 都要有固定案例。S2 起所有 skill 票都依賴這個工具驗收。

## 要做的事

- [ ] `evals/*.yaml` 格式：fixture 工作區狀態、一句需求、預期（載入的 skill、呼叫的工具序列、產出通過的 schema 與檢查）
- [ ] 工具 `eval <skill> [--case] [--repeat N]`：複製 fixture 到暫存目錄，用 headless 模式執行，讀 ledger 與產出做斷言
- [ ] 報告：每個案例通過與否、花費、回合數；可比較改前改後
- [ ] PR 模板加一欄「改了 SKILL.md 時附 eval 結果」

## 交付物

- `src/newsroom/eval/`、工具 `eval`、`schemas/eval-case.schema.json`
- `.github/PULL_REQUEST_TEMPLATE.md` 更新

## 驗收標準

1. Given 範本 skill 與一個案例，When eval，Then 產生報告並列出工具呼叫序列
2. Given 把 skill 的一條規則刪掉，When eval，Then 對應案例失敗
3. Given `--repeat 3`，When eval，Then 報告列出 3 次的通過率與花費

## 測試方式

pytest（以假的 `claude` 執行檔回放錄製的工具呼叫）；用真的 Claude Code 跑一次範本案例。

## 不在這張票的範圍

各 skill 的案例內容（各自的票）；CI 上跑真的 agent（成本考量，只在本機或手動觸發）。
