# T-016｜facts-verify 工具與抽事實步驟

| 負責人 | Sprint | 估點（人天） | 類型 | Epic |
|---|---|---|---|---|
| 周長曉 | S1 | 1 | feature | [E04-draft](E04-draft.md) |

**前置票**：[T-015](T-015.md)、[T-003](T-003.md)

**實作需求**：`DRF-FR-001`

## 背景

事實由 agent 依 `draft-content` skill 抽取（ADR-08 修訂），這張票做驗證工具，以及 skill 裡抽事實的那一段。下游的寫稿與引用檢查都依賴 facts.json 可信。

## 要做的事

- [ ] facts.json schema（加入 `schemas/`）
- [ ] 工具 `facts-verify <topic_id>`：schema、`cited_text` 在原文逐字存在（正規化全形半形與空白）、回填 `char_start`／`char_end`、`numbers` 與 `entities` 出現在摘錄或 claim
- [ ] `skills/draft-content/SKILL.md` 的「抽事實」段落：一句一個事實、附逐字摘錄、驗證失敗時怎麼修
- [ ] facts.json 記錄 sources 雜湊；雜湊沒變時 skill 沿用
- [ ] eval 案例：fixture topic 抽事實並通過驗證

## 交付物

- `draft/facts_verify.py`、工具 `facts-verify`
- `skills/draft-content/SKILL.md`（抽事實段）、`skills/draft-content/evals/facts.yaml`

## 驗收標準

1. Given 一個原文沒有的摘錄，When facts-verify，Then 指出是哪個 fact，結束碼為失敗
2. Given fixture topic，When 跑 eval，Then facts.json 通過驗證
3. Given topic 沒有任何來源，When 執行 skill，Then 工具回報 E_MISSING_SOURCE（blocked）

## 測試方式

pytest（facts-verify）；`newsroom eval draft-content --case facts`。

## 不在這張票的範圍

寫稿（T-017）。
