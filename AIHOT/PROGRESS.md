## 1. 現在能做什麼

**每天的題目清單**
- 自動去 33 個網站收新聞（官方部落格、科技媒體、電子報、Hacker News、GitHub 新版本、論文）。
- 同一件事被很多網站報導，會合成一則。
- 每則會算一個「熱度分數」，分成 S（超熱）、A（還不錯）、B（普通），熱的排前面，還會建議「適合做哪個節目、做成貼文還是影片」。
- 清單是一個文字檔（每天一份）。你只要在上面打勾、寫備註；程式不會蓋掉你寫的東西。
- 昨天沒勾的會帶到今天（標「昨日」），超過兩天就自動拿掉。
- 有哪個網站連續三次抓不到，會列在清單最下面提醒。

**自己丟網址進清單**
- 看到好題目，丟網址就能加進來；重複丟同一個網址（就算寫法不同）也只會有一筆，備註會累加。

**選好題目之後**
- 一個指令建立題目資料夾。兩則新聞其實是同一件事，可以合併成一個題目。
- 自動抓原文；如果文章裡提到官方公告、GitHub、論文，會一起抓回來。
- 抓不到的時候不會亂編，會請人把原文貼進指定的檔案。

**影片和圖片**
- 自動下載網頁上直接放的影片、動圖、主視覺圖（會先看網站允許不允許、不會一次狂抓、檔案太大或圖太小會跳過）。
- 可以下載 YouTube 影片。
- 把影片轉成剪輯用的格式、把旁白調成合適音量並去掉前後空白、找出影片的場景切換點。
- 有一份素材清單，會告訴你「這題做影片還缺什麼畫面」。

**維護**
- 一個指令建好整個工作資料夾；一個指令檢查電腦環境夠不夠。
- 每天早上自動檢查「下載功能有沒有壞掉」，並統計各種下載方式最近一個月的成功率。

## 3. 跟規格不一樣的地方（串起來之前一定要看）

1. **語言已經跟規格一致（Python）**，但目錄結構不完全照規格：規格寫 `collect/collectors/*.py`，我只有 `collect/` 底下的 `signals.py`、`manual.py`、`newsletters.py`、`changedetect.py`。RSS、JSON 列表、網頁列表的收集器已改寫成 Python，放在 `src/newsroom/engine/sources/`（見第 8 節）；X 搜尋與公眾號的收集器還沒改。
2. **每則題目的編號格式不同。** 規格是 `cand_` 加 12 個英數字；我的是 `cand_` 加 AIHOT 自己的編號。要三個人一起定資料格式（T-002）時對齊。
3. **「同一件事合併」用 AIHOT 的，不是規格那套。** AIHOT 是請 AI 模型判斷；規格要的是不用 AI 的規則與比對。熱度分級有照規格做，但吃的是 AIHOT 合併好的結果。
4. **新聞網站清單放的地方不同。** 在 `industry/sources.json`，不是規格的 `watchlist/sites.md`。
5. **每一則稿件只有檔案，沒有資料庫紀錄。** 稿件的狀態管理是楊舒媁負責的，我只放了一個檔案，等她的部分好了再接。
6. 工作資料夾裡的 `config.toml` 只是一個「這是工作資料夾」的記號，這套程式的設定在別的地方（`.env`、`site/`、`industry/`）。

## 4. 還沒確認過、要小心的地方

- **熱度的門檻是我隨便抓的初始值。** 規格要求「人工標出來的超熱新聞，至少 8 成要被判成 S 或 A」，這需要你們先挑一批當標準答案，我已經做好檢查用的工具（`newsroom backtest-heat`），但還沒有標準答案可以跑。實際看過：當天 Hugging Face 上最熱的論文（110 個讚）只得 37 分，被判成 B，我覺得偏低。
- **熱度分級還沒用「真的熱點新聞」看過。** 我這邊沒開 AI 模型，所以只看過手動丟的網址，沒看過 AIHOT 合併出來的熱點事件。
- **Vimeo 和 X 的影片下不了。** 它們現在都要登入才能下載。我不會想辦法繞過去，程式會告訴人「這個要登入」，並建議自己錄影，或提供自己帳號的登入檔。X 那邊我連一則真的推文都沒測到。
- **「抓得到文字」不等於「抓得對」。** 我 59 個網頁測試，57 個抓得到 200 字以上，失敗的 2 個是 openai.com（它不讓程式讀）。這只代表有抓到東西，沒有人工檢查內容正不正確。
- 場景切換、影片處理：只用人工做的假影片和少數真影片測過，沒有大量真實素材的驗證。
- AIHOT 原本的全部測試（2026-11-02 在 Linux 容器跑，Node 24）：1122 個，1063 通過、30 失敗、29 略過。在 Windows 上會失敗的 3 個「SIGTERM」測試在 Linux 全部通過，確認是 Windows 沒有真正 SIGTERM；完整測試在 Windows 上會卡住，Linux 不會。剩下的 30 個失敗是我準備的容器不齊全（沒先 build 網站、沒有 pg_dump、沒有 `.git`／外層 `skills/`），從錯誤訊息判斷與程式無關，但我沒有把容器補齊再重跑確認全綠。我新增的測試全部通過。另外在 Windows 上，完整測試同時建測試資料庫會互搶（單獨跑每個檔案都通過），可用 `--test-concurrency=1` 避開。
- 2026-11-03 在補齊的 Linux 容器（Node 24、`git`、`pg_dump 17`、`npm ci`、已 build 網站、外層 `skills/` 都在）重跑 AIHOT 原有測試：1122 個，**1093 通過、0 失敗**、29 略過；`test:standalone` 241 個全過；`npm run typecheck` 無錯誤。上一輪的 30 個失敗確認都是容器缺東西（最後 12 個是 `pg_dump` 版本 15 對不上資料庫 17）。`test:web` 在容器裡卡住不結束（`apps/web/tests/article-outline.test.ts` 附近），我手動中止，**沒有跑完**，原因沒查。
- 2026-11-03 整個網站和背景程式用 `docker compose up -d --build` 完整啟動成功（資料庫、setup、api、worker、web 都起來），`scripts/smoke.ts` 全部通過；33 個來源第一輪都抓成功。模型呼叫是關的（`MODEL_CALLS_ENABLED=false`）。

## 5. 已知的小缺點

- 手動丟網址進來時，沒指定標題會先去讀網頁自己的標題（og:title，沒有就用 <title>）；讀不到才用網址本身。
- 推特貼文的原文抓不了；YouTube 只抓到標題和說明，沒有字幕。
- 「這篇新聞引用的官方網站」是用比較粗的方式判斷，少數網址會判錯。
- 2026-11-03 已把 `industry/` 底下（提示詞 31 份、`taxonomy.ts`、`topics.json`、`sources.json`、`selection.ts`、`wording.ts`、範例檔、README）全部改成繁體，用 OpenCC（簡→台灣用語）轉換，再把幾個不適合的詞手動改回（例如「釋出」改回「發布」、公司名「位元組」改回「字節」）。分類的 `key`（網址用的）沒有動。標籤詞表一起改了（例如「模型发布」→「模型發布」），所以舊資料庫裡已經存的簡體標籤不會再對上；目前資料庫沒有跑過模型，沒有這種舊資料，但**若之後接上舊的資料庫要重打標籤**。測試裡寫死的舊標籤也同步改了（18 個檔案），完整測試 1127 個通過。

### 8.5 要小心的地方

- **佇列不互通。** Python 用自己的資料表（migration 0123），不與 Node 的 pg-boss 互通；切換時整個引擎要一起換，Node 佇列裡還沒處理的工作不會帶過去。
- **模型步驟只用假模型驗證過。** 提示詞、請求內容、結果解析、寫入都和 Node 一致，但真實模型的輸出品質沒有驗證過。
- **正文擷取靠樣本驗證。** 2,000 頁是我產生的、30 篇是真實的，全部一致，但真實世界的網頁更雜。
- **圖片像素不同。** 縮放與分享圖改用 Pillow，格式、尺寸、快取鍵與標頭一致，但像素不會與原版完全相同。
- **一些刻意的差異。** 結構不符時的錯誤文字（zod 與 Python 檢查措辭不同）；超過西元 9999 年的日期（單位填錯）Python 當成「時間未知」。
- **測試之間會互相影響。** 這次發現模型選擇的快取會在同一個行程裡留到下一個測試；已修好，但之後新增測試要注意清除這類快取。
- **沒有 push。** 所有改動只在我這台電腦的 `dev` 分支，約 106 個提交，沒有上傳。
